# 一、 模型应用工程架构的发展历程
模型应用工程 (Model Application Engineering)：一门系统化地将基础模型 (Foundation Model) 能力转化为可用、可靠、可持续运营的应用系统的工程学科。核心研究命题：如何在真实业务场景中，将模型的概率性输出转化为稳定、可控、有商业价值的应用功能。模型应用工程并非凭空诞生，它脱胎于传统机器学习工程、MLOps，随着基础模型的普及逐步演化而来。核心范式发生重大反转：**传统机器学习工程：数据→模型→产品；模型应用工程：产品→数据→模型**。整个演进可以划分为四个阶段。
### 阶段 1：传统机器学习工程时代（2012‑2020）

**核心范式：先训练模型，再交付产品**

- 业务模式：针对单一业务任务，采集标注数据，从零训练或者微调任务专用模型；例如风控、推荐、文本分类。
- 工程重心：**特征工程、数据集标注、模型训练、防止训练‑服务偏移**。MLOps 围绕模型训练、版本管理、模型部署展开。
- 系统特征：模型输出属于**封闭集合**，输出结果是有限类别，可使用传统单元测试、准确率、召回率做质量校验。
- 局限：每一个业务需求都要重新准备标注数据、重新训练模型；模型泛化能力有限，新增任务需要重做整套训练流程；无法处理开放式生成任务。

> 
> 这个阶段没有 “应用层适配” 的概念，工程的主要工作发生在**模型开发层**。

### 阶段 2：提示工程原型时代（2020‑2022，GPT‑3 之后）

**核心范式：消费现成预训练大模型，依靠提示词完成任务**

- 标志性事件：GPT‑3 发布，证明强大预训练模型可以通过提示词完成大量任务，不需要修改模型权重。
- 工程重心：提示词设计、少样本 / 思维链；开发者直接调用模型 API，几乎不做训练。
- 系统特征：最简原型，输入提示，接收模型输出。快速做 PoC，几分钟即可做出演示 Demo。
- 暴露的现实痛点：幻觉、输出格式不稳定、业务私有知识缺失、提示注入攻击；仅靠提示词无法生产可用系统。
- 行业认知误区：一度认为 “只要写好 Prompt 就能解决业务问题”，忽视外围工程体系。

### 阶段 3：LLM 应用工程 / LLMOps 时代（2022‑2024，ChatGPT 爆发）

**核心范式：提示词 + 外部上下文增强（RAG） + 简单微调，解决企业私有业务**

- 标志性事件：ChatGPT 发布，LangChain、LlamaIndex 等编排框架兴起，RAG 大规模落地，Agent 概念兴起。
- 工程重心：检索增强 RAG、提示模板管理、向量知识库、参数高效微调 LoRA、基础可观测。
- 系统特征：不再只依赖提示词；引入外部知识库补充模型知识；开始做输入输出防护、日志统计；企业大量做内部知识库问答系统。
- 新出现的工程难题：
  1. 模型输出是**概率开放式输出**，传统准确率指标失效，传统单元测试不足以保障质量；
  2. 幻觉、事实一致性、工具调用失败；
  3. Agent 带来 IO 阻塞、成本暴涨、不可控；
  4. 缺少标准化评估手段，通用公开 benchmark 和真实业务差距巨大。

> 
> 这一阶段 LLMOps 更多聚焦工具链，但是缺少一套完整面向业务的系统架构方法论，很多团队把框架当成架构本身。

### 阶段 4：模型应用工程范式成型（2024 至今）

> 
> 参考《AI 工程：大模型应用开发实战》Chip Huyen 提出的工程思想：工具迭代很快，底层工程原则更加持久，重点关注如何把概率模型转化为可持续运营的业务系统。

**核心范式：演进式架构思想 + 全链路评估 + 业务反馈闭环 + 人在回路，面向生产可持续运营**

1. 重心上移到**应用开发层**，优先做应用层适配，微调是后置备选手段；手段优先级：提示工程 → RAG 上下文 → 结构化输出约束 → 数据增强 → 微调。
2. 明确区分原型 PoC、准生产、大规模生产系统；倡导**由简入繁演进式架构**，禁止一上来就搭建复杂 Agent 系统。
3. 评估成为一等公民：离线业务评测集、线上抽样评估、AI‑as‑Judge（AI 当裁判）评估流水线，评估贯穿整个生命周期。
4. 反馈闭环是系统持续迭代的核心：收集用户显式 / 隐式反馈，回流到提示、知识库、评测集、微调数据集。
5. 正视模型概率性本质：不以追求 100% 正确为目标，追求**可控、可观测、错误可拦截、错误可迭代**。
6. 完整三层技术栈：应用开发层、模型开发层、基础设施层；不再把 AI 工程等同于调模型或者调框架。

**和 LLMOps 的区别**

- LLMOps：偏向工具、运维、模型生命周期；
- **模型应用工程**：以业务价值为出发点，研究整套系统架构、组件演进、评估、反馈闭环，解决 “概率模型如何交付商业可用功能” 的核心命题。

> 
> 发展历程小结：
> 传统 ML 工程：**为任务造模型**；
> 模型应用工程：**拿现成基础模型，搭建整套应用系统去适配业务**。
