为什么传统软件测试对大模型系统失效
传统软件依靠单元测试、准确率、回归测试保障系统质量。但大模型属于概率开放式输出系统：同样输入，模型可能返回不一样的回答；不存在绝对标准答案；公开 Benchmark 高分，不等于业务场景可用。
在模型应用工程第四阶段范式中，评估不再是上线前的收尾工作，而是一等公民，贯穿需求、POC、准生产、上线运营全生命周期。评估的产出直接驱动提示词修改、知识库迭代、Harness 约束调整、数据集优化。
读完本章你将理解：
• 为什么传统测试手段在大模型面前失效；
• 如何搭建离线评测集；
• AI‑as‑Judge 裁判模型的用法与陷阱；
• 如何构建线上业务反馈闭环；
• 如何搭建可自动化运行的评估流水线。
输出的概率开放式特征：没有绝对标准答案
单元测试、准确率、召回率的适用边界与局限性
